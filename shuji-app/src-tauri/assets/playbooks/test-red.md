# 测试僵局排查

## 现象

`run_tests` 多次失败，测试持续不通过。

## 排查步骤

1. **确认失败根因**：阅读测试输出中的第一个失败，区分编译错误 vs 断言失败 vs 超时
2. **检查依赖**：确保 `Cargo.toml` / `package.json` 依赖完整，feature flags 正确
3. **隔离问题**：只运行单个失败测试文件，减少干扰
4. **查看相关源码**：用 `read_file` 确认实现与契约签名一致

## 决策树

### 如果你是刑部尚书（测试质量门）

**你的职责是报告失败，不是修复代码。**

- 分析失败原因（编译错误 / 断言失败 / 超时 / 环境问题）
- 生成结构化质量报告（`create_document(type="rprt")`）
- 将报告路由回尚书令
- **不要修改生产代码或工部单元测试**——你只能写 `tests/integration/` 下的集成测试
- 连续 3 轮测试失败 → 立即生成报告并路由，不要继续重试

### 如果你是工部尚书（实现者）

- 编译错误 → 检查导入和类型定义，用 `edit_file` 修复
- 断言失败 → 检查实现逻辑 vs 契约，用 `edit_file` 修复
- 超时 → 考虑缩短测试或增大 timeout
- 连续 3 轮相同 exit_code → 请求协助或重新审视方案
