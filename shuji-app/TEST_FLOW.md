# 枢机 标准测试流程

> 手动逐步验证完整工作流。预期耗时：5–10 分钟。

## 前置条件

```bash
cd shuji-app
npm run tauri dev
```

---

## 测试 1：完整交付流程（基本路径）

### Step 1 — 创建项目
1. 点击 **浏览** → 选择一个空目录（或在输入框手动输入路径）
2. 点击 **打开**
3. 弹出"创建新项目"表单 → 填写：
   - 项目名称：`测试项目`
   - 皇帝目标：`帮我实现一个ERP管理系统`
4. 点击 **创建项目**
5. ✅ 自动跳转到项目面板，左侧显示"皇帝目标"，右侧显示"陛下有何吩咐？"

### Step 2 — 下达指令
6. 在输入框输入：`开始工作`
7. 按 Enter 或点 **发送**
8. ✅ 聊天区出现"内阁：遵旨。陛下目标是「开始工作」…"
9. ✅ 左侧进度条开始更新

### Step 3 — 等待方案审批
10. 系统自动推进（无需操作）
11. ✅ 出现"整体方案已完成设计并通过门下省审查，呈请皇帝御批"消息
12. ✅ 消息下方出现选项按钮：**A. 准** **B. 准，但** **C. 驳** **D. 暂缓** **E. 钦此**

### Step 4 — 皇帝决策
13. 点击 **A. 准**
14. ✅ 系统自动推进，依次显示：
    - "阶段1详细设计完成"
    - "阶段1审查通过，呈请皇帝御批"
15. ✅ 再次出现选项按钮

### Step 5 — 再次决策
16. 点击 **A. 准**
17. ✅ 系统自动执行阶段1（吏部拆解 → 兵部测试 → 工部编码 → 刑部 → 礼部 → 户部）
18. ✅ 左侧阶段1显示"执行：已完成"
19. ✅ 自动开始阶段2设计、审查、等待决策

### Step 6 — 重复审批直到交付
20. 循环选 **A. 准**，直到出现"项目已全部完成，交付归档"
21. ✅ 左侧显示"已交付"

---

## 测试 2：驳回流程（分支路径）

清除 `.shuji/` 目录后重开项目，或创建新项目。

### Step 1 — 下达指令
1. 输入：`做一个简单的CRUD系统`
2. ✅ 系统推进到方案审批

### Step 2 — 选择驳回
3. ✅ 看到选项时，点击 **C. 驳**
4. ✅ 出现"方案审查未通过（驳回第1次），已退回中书省修改"
5. ✅ 系统自动重新设计并再次审查

### Step 3 — 重复驳回（测试 3 次升级机制）
6. 连续选 **C. 驳**，观察驳回次数递增
7. ✅ 第 3 次驳回后出现"设计已驳回3次，呈请皇帝御批"
8. ✅ 此时选 **A. 准** 继续执行

---

## 测试 3：执行阻塞流程

### Step 1 — 下达指令
1. 创建新项目，输入：`生成一个数据分析系统`

### Step 2 — 一路批准
2. 每次出现选项选 **A. 准**

### Step 3 — 观察执行阻塞
3. MockAgent（兵部）有 15% 概率触发阻塞
4. ✅ 如果触发阻塞，出现"执行发现严重问题"消息和选项
5. ✅ 选 **A. 退回修改** 退回设计阶段
6. ✅ 选 **C. 终止** 终止项目
7. ✅ 如果没有触发阻塞，继续自动执行直到交付

---

## 测试 4：暂缓/终止流程

### Step 1
1. 同测试 1，推进到方案审批

### Step 2 — 暂缓
2. 点击 **D. 暂缓**
3. ✅ 出现"项目已暂缓"
4. ✅ 左侧状态显示"已暂停"

### Step 3 — 终止
5. 输入任意文字（暂缓状态下没有下一步）
6. ✅ 观察系统反馈

---

## 验证清单

每条完成打 ✓：

- [ ] 项目创建正常
- [ ] 下达指令后自动推进
- [ ] 整体方案设计 → 审查 → 等待皇帝
- [ ] 皇帝选"准"后继续执行
- [ ] 阶段设计 → 审查 → 等待皇帝
- [ ] 阶段执行（吏部→兵部→工部→刑部→礼部→户部）
- [ ] 驳回次数递增，3 次后升级
- [ ] 执行阻塞后皇帝可决策
- [ ] 暂缓/终止正常工作
- [ ] 所有阶段完成后显示"已交付"
- [ ] `.shuji/logs/` 下各角色独立日志文件
