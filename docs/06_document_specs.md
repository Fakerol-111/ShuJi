# 06 — 传递件规范（Document Specs）

## 三大文书类型

| 类型 | 方向 | 说明 |
|------|------|------|
| **敕令** | 下行（上级→下级） | 单向指令，无需回复 |
| **奏折** | 上行（下级→上级→皇帝） | 需皇帝决策，交互式 |
| **移文** | 平行（平级部门间） | 通知、送审等 |

## 通用头部

所有传递件统一以元数据开头：

```markdown
# [敕令|奏折|移文] — 一句话事由

## 元数据
- 发件: [部门]
- 收件: [部门]
- 日期: [ISO 8601]
- 优先级: 普通 / 紧急
- 关联任务: [任务 ID]
- 关联文档: [文档 ID]

## 正文
<内容>

## 请求
<期望收件方做什么>

## 附件
<如有>
```

## 敕令（下行文）

**用途**：上级对下级下达指令。单向传递，无需回复，接收方直接执行。

**示例**：
```markdown
# 敕令 — 启动 ERP 阶段1 执行

## 元数据
- 发件: 内阁
- 收件: 尚书省
- 日期: 2026-05-07
- 优先级: 紧急
- 关联任务: TASK-ERP-001

## 正文
皇帝于 2026-05-07 御批通过「ERP 阶段1 用户模块详细设计方案」。

## 请求
请尚书省即日起组织六部，按方案执行阶段1 用户模块开发。
```

## 移文（平行文）

**用途**：平级部门间传递信息。接收方按"请求"字段自行处理。

**示例**：
```markdown
# 移文 — 送审 ERP 阶段1 详细设计方案

## 元数据
- 发件: 中书省
- 收件: 门下省
- 日期: 2026-05-07
- 优先级: 普通
- 关联任务: TASK-ERP-001
- 关联文档: DESIGN-ERP-PHASE1-v2

## 正文
<完整的方案内容>

## 请求
请门下省依皇明祖训审查本方案。
```

## 奏折（上行文）

**用途**：需要皇帝决策的事项上报。**交互式**——需附带选项供皇帝选择。

### 奏折格式

```markdown
# 奏折 — [事由]

## 元数据
- 呈报: [来源部门] → 皇帝
- 日期: [ISO 8601]
- 优先级: 普通 / 紧急
- 关联任务: [任务 ID]

## 背景
<为什么会有这事>

## 要点
- <核心内容>
- <关键决策项>

## 皇帝御批

请选择一项（可编辑修改）：

A. 准 — ___________________________

B. 准，但 — 补充以下修改：_________

C. 驳 — 驳回：_____________________

D. 暂缓 — 先放着：_________________

E. 钦此 — 皇帝自己的想法：_________
```

### 选项说明

| 选项 | 含义 | 后续流程 |
|------|------|---------|
| **A. 准** | 完全同意，按方案执行 | 内阁传旨执行 |
| **B. 准，但** | 同意大方向，但需做指定修改 | 内阁传旨修改后执行 |
| **C. 驳** | 方案不可行，退回重做 | 内阁传旨退回原部门 |
| **D. 暂缓** | 方向正确但时机未到 | 方案冻结，日后可能重启 |
| **E. 钦此** | 皇帝另有想法 | 以皇帝意见为准，内阁传达 |

- 选择后，皇帝可编辑选项中的 `____` 部分补充说明
- 内阁根据皇帝选定的选项，传旨给对应部门执行

### 奏折示例

```markdown
# 奏折 — 呈批 ERP 系统整体方案

## 元数据
- 呈报: 内阁 → 皇帝
- 日期: 2026-05-07
- 优先级: 普通
- 关联任务: TASK-ERP-001
- 关联文档: DESIGN-ERP-OVERALL-v1

## 背景
皇帝提出"做一个 ERP 系统"，中书省已完成整体方案设计，门下省审查通过。

## 要点
- 架构：前后端分离，RBAC 权限模型
- 3 个阶段：用户模块 → 业务模块 → 报表模块
- 预估工期：6 周

## 皇帝御批

A. 准 — ___________________________

B. 准，但 — 补充以下修改：_________

C. 驳 — 驳回：_____________________

D. 暂缓 — 先放着：_________________

E. 钦此 — 皇帝自己的想法：_________
```

## 传递件流转规则

| 规则 | 说明 |
|------|------|
| **所有传递件必须有 `请求` 字段** | 接收方读"请求"即知自己要做什么 |
| **奏折必须附带选项** | 皇帝只做选择题，不做事先填空题 |
| **敕令和移文不需要回复** | 接收方自行处理即可 |
| **每个传递件关联任务和文档** | 便于追踪上下文 |
