# 03 — 完整决策流程（Process Flow）

> 从皇帝下达目标到任务完成的完整流转路径，含所有分支情况。

## 并行机制

```
阶段设计 与 阶段执行 可并行：

阶段1 设计 ──→ 审查 ──→ 审批 ──→ 阶段1 执行 ──→ 完成
                                              │
                   阶段2 设计 ──→ 审查 ──→ 审批 ──→ 阶段2 执行 ──→ ...
```

即：尚书省执行阶段1 的同时，中书省可以开始设计阶段2。

## 权限申请子流程

```
执行过程中，某部门需要特定权限
    ↓
该部门 → 尚书省（统一代理）
    ↓
尚书省 → 制司
    ↓
制司判断：
  ├── 有权批准 → 直接批准，记入日志
  └── 无法决定 → 内阁 → 皇帝决策
```

## 皇帝叫停子流程

```
皇帝在任何时刻说"停"
    ↓
立即停止一切执行
    ↓
内阁记录已完成的进度和状态
    ↓
保存当前上下文（便于以后恢复）
```

## 映射到软件开发环节

| 流程阶段 | 对应软件工程环节 |
|----------|----------------|
| 皇帝下达目标 | 产品愿景 / 业务需求 |
| **中书省模糊需求澄清** | **需求调研 / 需求澄清** |
| 中书省出整体方案 | 架构设计 / 系统设计 |
| 门下省审查整体方案 | 架构评审 |
| 皇帝审批整体方案 | 立项决策 |
| 中书省出阶段详细设计 | 详细设计 / 接口定义 |
| 门下省审查阶段设计 | 设计评审 / 同行评审 |
| 皇帝审批阶段设计 | 迭代规划批准 |
| 吏部拆解任务 | 任务分解 / 工作分解结构（WBS） |
| 兵部写测试用例 | 测试设计 / TDD 红阶段 |
| 工部编码实现 | 编码开发 |
| 刑部检查 | 静态分析 / 边界测试 |
| 礼部检查 | 代码审查 / 规范检查 |
| 户部记录 | 项目追踪 / 成本核算 |
| 尚书省交付 | 交付 / 发布 |
| 执行中反馈问题 | Bug / 变更请求 / 设计缺陷 |
| 反馈 → 皇帝决策 | 变更控制委员会（CCB）决策 |
