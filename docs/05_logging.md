# 05 — 日志规范（Logging）

## 总则

- 所有部门必须记录日志
- 日志格式统一，便于户部归档和制司审计
- ID 按各部门独立编号

## ID 规则

| 部门 | ID 前缀 | 编号管理 |
|------|---------|---------|
| 内阁 | `内阁-` | 内阁自管 |
| 中书省 | `中书省-` | 中书省自管 |
| 门下省 | `门下省-` | 门下省自管 |
| 制司 | `制司-` | 制司自管 |
| 六部 | `六部-` | 户部统一管理（尚书省内部通用） |

编号按时间递增：`内阁-001`、`内阁-002`……

## 通用日志格式

所有日志使用统一 JSON 结构：

```json
{
  "id": "门下省-001",
  "timestamp": "2026-05-07T14:30:00+08:00",
  "source": "门下省",
  "type": "审查",
  "summary": "驳回 ERP 用户模块阶段设计方案",
  "details": "方案中 API 命名未遵循 RESTful 规范，路径使用了动词",
  "decision": "驳回",
  "ref": {
    "taskId": "TASK-ERP-001",
    "docId": "DESIGN-ERP-PHASE1-v2"
  }
}
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 各部门独立编号，格式：`{前缀}-{数字}` |
| `timestamp` | 是 | ISO 8601 格式 |
| `source` | 是 | 日志来源部门 |
| `type` | 是 | 日志类型：设计 / 审查 / 权限 / 执行 / 皇帝决策 |
| `summary` | 是 | 一句话摘要，便于快速查阅 |
| `details` | 否 | 详细内容 |
| `decision` | 否 | 涉及的决定（通过/驳回/批准/上报/准/驳/停） |
| `ref` | 否 | 关联的任务 ID 和文档 ID |
| `ref.taskId` | 否 | 关联的任务 |
| `ref.docId` | 否 | 关联的文档 |

### type 取值范围

| type | 使用部门 |
|------|---------|
| 设计 | 中书省 |
| 审查 | 门下省 |
| 权限 | 制司 |
| 执行 | 六部 |
| 皇帝决策 | 内阁代记 |
| 调度 | 尚书省 |

## 日志流向

```
各部门产生日志
    ↓
六部日志 → 户部统一归档
其他部门 → 各自保留
    ↓
制司审计 → 读取各部门日志
尚书省汇报 → 读取户部日志
```
